## ケース数の数え方

```sh
# 対象の 10 ファイル（追加 A と改名 R だけ）
git -C pekko diff --diff-filter=AR -M --name-status v1.7.1 v2.0.0 -- docs/src/test

# Java は JUnit 5 の @Test を数える
git -C pekko show v2.0.0:docs/src/test/java/jdocs/stream/operators/source/QueueMigrationDocTest.java \
  | grep -c '@Test'

# Scala は ScalaTest の in { を数える
git -C pekko show v2.0.0:docs/src/test/scala/docs/stream/operators/source/QueueMigrationDocSpec.scala \
  | grep -c 'in {'
```

数えるには v1.7.1 と v2.0.0 の両方のタグが要る。タグを 1 つだけ取る `--depth 1` の clone では
2 つの版を比べられないので、この 10 件は測れない（原典を用意する
`tools/pekko-source/prepare_pekko_source.sh` の clone も `--depth 1 --branch v2.0.0` である）。
ここでは両方のタグを持つ clone で測った。

`test_cases_approx` は既存の `docs` ノードと同じく、この実測値をそのまま書いた。0 は
テストメソッドを持たないファイル（コンパイルだけの例と、ほかのテストが使うヘルパ）である。

## なぜ `do_not_port` か

`docs` モジュールは論点 20 の決定（2026-11-13、オーナー）で移植対象外としている。台帳の
`docs/src/test/...` の 173 ノードはすべてこの決定で `do_not_port` になっている。この 10 件も
同じモジュールの同じ場所（`docs/src/test`）にあるので、同じ扱いにした。新しい決定ではない。
`triage.reason` も既存 173 件と同じ文面
（「論点 20 の決定（2026-11-13、オーナー）。docs モジュールは移植対象外とする」）を書いた。

## 台帳への反映

既存の `docs` ノードと同じ形で 10 ノードを足した（`kind: test`、`pekko.module: docs`、
`name: docs:<クラス名>`、`status: do_not_port`、`triage.kind: do_not_port`、
`verified_against: v2.0.0`、`cases`・`needs`・`depends_on_impl`・`rust`・`goal` は既存
`docs` ノードと同じ空または null）。並びは既存の `docs/src/test/...` と同じ規則
（クラス名、同じクラス名なら `id`）に合わせた。`docs` モジュールのノードは 173 から 183 に
なった。

改名の 2 件（#8・#9）は `id` の付け替えではなく、新しいノードを足している。旧パス
`docs/src/test/scala-jdk9-only/docs/stream/operators/source/{AsSubscriber,FromPublisher}.scala`
は台帳に無く、台帳に `scala-jdk9-only` のノードも無い（`grep -c 'scala-jdk9-only'
ledger/nodes.yaml` は 0）。付け替える相手が無いので、v2.0.0 のパスで新しく足す。
