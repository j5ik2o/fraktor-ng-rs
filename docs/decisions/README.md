# docs/decisions — 設計判断の受け皿

ここには設計判断を「提案 → 承認 → 決定」の状態付きで置く。

## ルール

- Fable を含む外部モデル／エージェントからの回答は、まず**提案（draft）**としてここに受ける。
  提案が置かれただけでは設計設定にはならない
- 設計設定になるのは、ユーザーが承認したものだけである。承認されたものは状態を
  `accepted` に変え、承認日と根拠（どの事実層に基づくか）を記録する
- 却下された提案も消さない。状態を `rejected` にし、理由を1行残す
  （同じ提案が別経路で再浮上したときに、判断済みだと分かるようにするため）
- 事実層（`docs/baseline/`）と判断層（ここ）を混ぜない。事実は台帳が正であり、
  ここに書くのは事実の上での判断だけである

## 現在の設計課題（Fable 表紙メモの依頼範囲から転記）

`docs/baseline/pekko-v1.7.1/cover-memo.md` の依頼範囲5項目が、そのまま設計課題である。

1. ノード粒度（モジュール／テストクラス／テストクラス群）
2. 辺の種類の定義（実装依存／テスト基盤依存／意味的依存と、スケジューリングへの効かせ方）
3. ゴールの切り方（TAKT manager へ渡すゴールの分割ポリシー。コンフリクト回避と
   provider 配分を含む）
4. 最初の縦切り（TestKit 基盤＋最初のテスト群をどのモジュールで切るか）
5. 状態のロールアップ（未移植 / red / green / 移植しない → モジュール合格率と全体進捗）

各課題は、決まり次第ここに1件ずつファイルを作る。
