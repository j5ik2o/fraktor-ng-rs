# use-placement（旧 use-placement-lint、`use_mod_placement`）

旧 lint はすでに syn でファイルを読み直していた。分類と走査はそのまま写した。

## 旧 lint から写したもの

- `classify_item` のアイテム分類。`use` と、本体を持たない `mod` 宣言は配置対象。
  `extern crate`、type alias、インラインモジュールは数えない。それ以外は「その他」
- `enforce_module_items`。「その他」の後に現れた配置対象を違反にする。インラインモジュールの中は、
  モジュールごとに同じ判定をやり直す
- `detect_block_local_uses`。「その他」のアイテムの中にある `use` をすべて違反にする
  （関数本体、メソッド本体、ブロック）。スパイクはこの検出を写していなかった
- 報告位置はアイテムの先頭で、属性を含む（旧 `item.span()`）。`#[cfg(test)] mod tests;` は属性の行で報告する

## 写せなかったもの、変えたもの

- `Item::Verbatim` は旧 lint と同じく「その他」に入れた。スパイクは無視していた
- テスト、ベンチ、example のファイルを対象外にした。旧 lint にパスの除外は無い。対象外にするのは次のとおりである
  - `tests` ディレクトリの下。ただし直後が `ui` の `tests` は数えない（このチェッカー自身の UI フィクスチャを
    検査するため。type-per-file と ambiguous-suffix が旧 lint から引き継いだ扱いと同じ）
  - `benches` ディレクトリの下と、`examples` ディレクトリの下
  - ファイル名が `tests.rs`、`*_test.rs`、`*_tests.rs`（tests-location がテストファイルとみなす名前と同じ）

  判定は、コマンドラインで渡したパスのままの形で行い、絶対パスには直さない。親ディレクトリの名前に
  左右されないよう、verify_green は相対パスを渡す。理由は下の「テストコードの扱い」にある

## 例外規定と抑制

- 旧 lint に専用の抑制は無かった。新チェッカーでは共通のコメント指定が使える

## 既知の限界

- マクロ呼び出しの中の `use` は見えない（旧 lint も同じ）

## テストコードの扱い（2026-11-11 に決定）

旧 CI の実効の挙動に合わせて、テスト、ベンチ、example のファイルを対象外にした。決定は 2 回に分かれている。
最初に `tests` の下、`benches` の下、`*_test.rs` を対象外にし、続けて `tests.rs`、`*_tests.rs`、`examples` の下を
足した。後の 3 つは、tests-location がテストファイルとみなす範囲と揃えることと、example が旧 CI の対象外
だったことによる。

- 旧 lint の実装にパスの除外は無い。ただし旧 CI は lib ターゲットだけで dylint を走らせていた
  （旧 `scripts/ci-check.sh` の dylint の箇所に、「既定の `cargo dylint` は lib ターゲットだけで走るため、
  `#[cfg(test)]` モジュールはどの lint からも visit されない」とある）。旧 lint は、コンパイラが訪れたアイテムの
  ファイルを syn で読み直す作りなので、テストやベンチのときだけコンパイルされるファイルは一度も読まれなかった
- 新チェッカーはファイルを直接読むので、除外が無いとテストファイルも検査する。旧コーパス（`modules/`、
  2,689 ファイル）では 248 件が出て、すべてテストかベンチのファイルにあった（関数内の `use` が 245 件、
  後置の `use` が 3 件）。対象外にした後は 0 件である。対象外は 908 ファイル（`*_test.rs` が 817、`tests` の下が 88、
  `benches` の下が 3）、対象は 1,781 ファイルである
- 対象のファイルの中にある `#[cfg(test)]` のコードは、対象のままである。旧 lint は読み直したファイルの全体を
  syn で見ていて、syn は cfg を評価しない。旧 UI テストの `cfg_test_mod_warn` は、関数の後に置いた
  `#[cfg(test)] mod tests;` を違反にしている。インラインの `#[cfg(test)] mod x { }` の中も同じ走査を通る
- 旧コーパスの対象ファイルには、`#[cfg(test)]` の `mod` 宣言が 811 件あり、すべて冒頭に置かれていて違反は無い。
  インラインの `#[cfg(test)]` モジュールは 0 件なので、その中の扱いは旧コーパスでは確かめられない
  （tests-location が本番ファイルの `mod tests { }` を禁じている）
- 旧コーパスの検査範囲に、`tests.rs`、`*_tests.rs`、`examples` の下のファイルは無い。この 3 つを足しても、
  対象外のファイル数（908）と全ルールの件数（132）は変わらない。除外が効くことは、合成フィクスチャ
  （`tests/ui/synthetic/use-placement/crates/sample/`）で確かめている
- 対象のファイルにある `#[cfg(test)]` のコードを対象のままにすることと、`tests/ui` の下を対象のままにすることも、
  同じ日に決定した。クレートが `tests/ui/` に trybuild などのフィクスチャを置くと、そのファイルは検査される

## 要判断

なし。テストコードの扱いは、上のとおり決定済みである。
