# module-wiring（旧 module-wiring-lint、`no_parent_reexport`）

旧 lint は HIR のモジュール木と名前解決を使っていた。新チェッカーは `mod foo;` を rustc と同じ規則でファイルに解決し、
子モジュールがあるかどうかを、そのファイルの構文から判定する。旧 UI の 28 ケースはすべて一致した。

## 旧 lint から写したもの

判定の順序は旧 `evaluate_mod` と `evaluate_use` のままである。最初に当たった規則で報告し、その宣言の判定を終える。

### モジュール宣言（旧 `evaluate_mod`）

インラインの `mod m { ... }`、ファイルの `mod m;`、関数本体の中の `mod` のすべてを見る。

1. **`#[path]`**：`#[path = "..."]` が付いた宣言は違反。報告位置は属性の行である。
   旧 lint の `Attribute::Parsed(AttributeKind::Path)` に当たるのは、syn の `#[path = "<文字列>"]` 属性である
2. **sibling test hook**：次の条件をすべて満たす `#[path]` は許す。許した宣言は、`include!` と可視性も判定しない。
   旧 `is_allowed_sibling_test_path_attr` を写した
   - モジュール名が `tests`
   - `#[path` の直前にある空でない行が、空白を除くと `#[cfg(...)]` になり、その述語が test を必須とする。
     test を必須とする述語は `test` と、どれかの引数が test を必須とする `all(...)` である（旧 `cfg_expr_requires_test`）。
     旧 lint と同じくテキストで判定する
   - パスに `/` も `\` も含まない
   - パスが「宣言しているファイルの stem」に `_test.rs` を付けたもの
3. **`include!`**：宣言のテキスト（属性を除き、`mod` から最後のトークンまで）に `include!(` があれば違反。報告位置は `include!` である。
   旧 `find_include_invocation_span` のテキスト走査を写した。空白を除いた直前の文字が英数字、`_`、`#`、`/` のどれかなら、その出現は飛ばす
4. **prelude**：モジュール名が `prelude` なら、ここで判定を終える
5. **末端モジュール**：子モジュールを持たないモジュールを末端と呼ぶ。末端でなければ、ここで判定を終える。
   旧 `is_leaf` は `hir_module_items(module).free_items()` に `ItemKind::Mod` があるかを見ていた。この一覧にはモジュール直下のアイテムに加えて、
   関数本体など、アイテムの中に入れ子になったアイテムも入る。入れ子のモジュールの中身は入らない。syn でも同じ範囲を走査する
   （`module_items::declared_modules`）。インラインモジュールは本体を見る。`mod foo;` は解決したファイルを見る
6. **可視性**：末端モジュールの宣言に可視性が書かれていれば違反。`pub`、`pub(crate)`、`pub(super)`、`pub(self)`、`pub(in ...)` のすべてが当たる。
   旧 lint の条件（`Public` なら違反、`Restricted(scope)` なら `scope != 親` か可視性が書かれていれば違反）は、可視性が書かれているかどうかと同値である。
   報告位置は可視性の位置で、属性を含まない

### 再エクスポート（旧 `evaluate_use`）

- **公開の判定**：可視性が書かれた `use` だけを見る。旧 `is_public_use` は、親モジュールに限定された可視性でも、書かれていれば再エクスポートとみなした。
  したがって、これも可視性が書かれているかどうかと同値である
- **prelude**：`use` を含むモジュールの名前が `prelude` なら見ない。旧 `is_prelude_module` は def path の最後のセグメントを見ていた。
  インラインモジュールの名前は識別子で決める。ファイルのモジュールの名前は、下の「クレートのルートの判定」で決める
- **use 木の分解**：rustc は `use a::{b, c::*};` を葉ごとの import（`a::b` と glob の `a::c`）とリストの幹に分ける。旧 lint は幹を飛ばし、葉ごとに判定した。
  新チェッカーも葉ごとに分ける（`import::lower`）。`a::{self}` は `a` の import になる（rustc の lowering と同じ）。
  先頭の `::` は、rustc の `{{root}}` に当たるセグメント `::` として扱う。
  報告位置は、木の一番外側なら `use` アイテムの可視性、`{...}` の中なら葉の先頭である（旧 UI の `11:18` と同じ列になる）

葉ごとの判定（この順に見る）：

1. セグメントが 1 つの単一 import は違反。例：`pub use Thing;`、`pub use child::{self};`
2. **special segment**：先頭のセグメントが `self`、`super`、`crate` のどれかなら違反
3. **`as`**：束縛名が最後のセグメントと違えば違反。`as _` も当たる
4. **直属親**：先頭のセグメントが、`use` を含むモジュールの子モジュールの名前でなければ違反。子モジュールは末端判定と同じ範囲
   （関数本体の中を含む）から探し、名前が一致する最初の `mod` を使う。外部クレートや enum から始まるパスも、旧 lint と同じく違反になる
5. **末端モジュール**：その子モジュールが末端でなければ違反

## 写せなかったもの、変えたもの

- **モジュール木をファイル配置から作る。** rustc（`rustc_expand::module`）と同じ規則でファイルを探す
  - クレートのルート、`mod.rs`、`#[path]` で読み込まれたファイルでは、`mod foo;` は同じディレクトリの `foo.rs` か `foo/mod.rs` を指す。
    それ以外のファイル `bar.rs` では、`bar/foo.rs` か `bar/foo/mod.rs` を指す
  - 両方の候補があるとき、rustc はエラーにする。新チェッカーは、そのモジュールが末端かどうかを判定しない
  - インラインモジュール `mod m { ... }` の中では、ディレクトリに `m` を足す。インラインモジュールの `#[path = "d"]` は、ディレクトリとして連結する
  - `#[path = "p"]` 付きの `mod foo;` は、そのモジュールのディレクトリからの相対パスとして解決する
- **クレートのルートの判定（近似）。** 名前解決が無いので、どのファイルがクレートのルートかを、ファイル配置から決める
  - `lib.rs` と `main.rs` はクレートのルートとみなす
  - `mod.rs` は、ディレクトリ名のモジュールとみなす
  - それ以外の `<dir>/<stem>.rs` は、親になりうるファイルが `mod <stem>;` を `#[path]` なしで宣言していれば、モジュール `<stem>` とみなす。
    どれも宣言していなければ、クレートのルートとみなす
  - 親になりうるファイルは、`<dir>` とその祖先のディレクトリ `A` ごとに、`A/lib.rs`、`A/main.rs`、`A/mod.rs`、`A` と同名の `A.rs` である。
    `A` が `<dir>` より上なら、間のディレクトリ名と同じ名前のインラインモジュールを順にたどった先で宣言を探す
  - この規則では、`tests/it.rs`、`src/bin/x.rs`、`examples/x.rs`、旧 UI のケースファイル、宣言されていない孤立したファイルが、クレートのルートになる
- **cfg を評価しない（近似）。** 旧 lint は cfg を適用した後の木を見ていた。新チェッカーは、すべての cfg 分岐のアイテムを判定する。
  ただし、末端判定で子モジュールを数えるときだけ、test を必須とする `cfg` が付いた `mod` は数えない（要判断 1）
- **`#[cfg_attr(..., path = "...")]` も `#[path]` とみなして違反にする。** cfg_attr の条件は評価しない（要判断 4）。
  報告位置は宣言の位置である。旧 lint の `#[path` の文字列探索はこの形を見つけられず、宣言の位置で報告したので、それに合わせた。
  sibling test hook として許すことはない。旧 lint でも、直前の行が `#[cfg(` で始まらないので許されなかった
- **同じ位置の `include!` を 1 件にまとめた。** 外側のインラインモジュールも、内側のモジュールにある `include!` を見つける。
  旧 lint はどちらの宣言でも報告したが、rustc は同じ診断を 1 度しか出さない。新チェッカーも 1 件にした
- **子モジュールのファイルが無い、候補が 2 つある、パースできない場合**は、そのモジュールが末端かどうかを判定しない。
  `pub mod` も `pub use` も報告しない（要判断 3）。旧 lint ではコンパイルエラーになる状態である
- **マクロが生成したモジュールと `use` は見えない。** 末端判定と子モジュールの検索については、旧 lint も `from_expansion()` で除外していたので、結果は同じである。
  一方、ローカルの `macro_rules!` が生成した `pub mod` や `pub use` そのものは、旧 lint では報告されたが、新チェッカーでは報告できない
- **名前解決をしない。** `pub use child::X` の `child` がその子モジュールを指すかどうかは、名前の一致で決める。
  旧 `find_direct_child_module` も名前で探していたので、同じ結果になる。2015 edition のパス規則は扱わない
- **メッセージ**：旧 lint の primary、note、help を 1 行にまとめた。可視性違反の詳細は、宣言全体ではなく `pub mod name` までを引用する

## 例外規定と抑制

- 旧 lint の例外規定は prelude（宣言と `use` の両方）と sibling test hook の 2 つで、どちらもそのまま写した
- 旧 lint の `// allow module_wiring::no_parent_reexport`（直前の行か同じ行）は、共通のコメント指定
  `// syn-check: allow(module-wiring) -- <理由>` に置き換える。ルールは旧形式のコメントを読まない
- 抑制の範囲は旧 lint と違う。`allow` は次の構文要素の範囲全体にかかるので、インラインモジュールの前に書くと、
  中の宣言と `use` もすべて抑制する。旧コメントは、その 1 アイテムにしか効かなかった。行末のコメントでは抑制できないので、直前の行に書く
- 旧 UI の `allow_comment_ok.rs` は、旧コメントの行と、行末コメントの直前の空行をコメント指定に置き換えた（`SPEC.adaptations`）

## 既知の限界

- テキスト走査の癖を旧 lint からそのまま受け継いでいる
  - `include!` は、文字列リテラルやブロックコメントの中でも、直前の文字によっては拾う。`// include!(...)` は拾わない
  - ファイルの最上位に書いた `include!` は、どの `mod` 宣言のテキストにも入らないので拾わない
  - sibling test hook の `#[cfg(test)]` は、`#[path]` のすぐ前の行に限る。属性の順序が逆の場合、間にコメントや別の属性がある場合、
    同じ行の末尾にコメントがある場合は許さない
- cfg の分岐で同名のモジュールが複数あるとき、子モジュールの検索は最初の 1 つを使う
- 関数本体の中の `mod foo;` は、rustc では `#[path]` が無いとエラーになる。新チェッカーは、モジュールのディレクトリから解決する
- 配置（`--layout`）は使わない。どちらの配置でも述語は変わらない。合成テストで、同じ結果になることを確かめている

## 要判断

1. **`cfg(test)` だけの子モジュールを末端判定で数えない近似を採った。** 旧 lint の結果は、lint を走らせたビルドで変わった。
   テストビルドでは、sibling test hook（`#[cfg(test)] #[path = "foo_test.rs"] mod tests;`）を持つモジュールはすべて末端でなくなる。
   すると、親の `pub use foo::Foo;` がすべて違反になる。テストを sibling の `*_test.rs` に置く規約では、ほぼすべての末端モジュールが当てはまるが、
   旧 lint にこの組み合わせの例外は無い。一方で、sibling test hook の例外と `--test` 付きの UI ケースがあるので、
   テストビルドでも lint を通す意図はあったと読める。両方と矛盾しない読み方は、「末端判定は非テストビルドの木で行い、宣言はすべてのビルドで判定する」である。
   新チェッカーはこの読み方を採った。旧 fraktor-rs がどのビルドで dylint を走らせたかは、手元の資料（旧 `lib.rs`、UI テスト、棚卸し）では確認できなかった。
   すべての cfg を数える方式（旧 lint のテストビルドと同じ結果）に変えると、`tests/module_wiring.rs` の `test_only_child_modules_do_not_make_a_branch` が落ちる
2. **クレートのルートを判定する近似規則**（宣言している親が見つからなければルートとみなす）を採った。
   Cargo.toml を読んで target の path を知る方法もあるが、toml パーサーの依存が要るので採らなかった。次の場合は判定を誤る
   - `tests/it.rs` が `mod common;` で `tests/common.rs` を宣言する場合。`common.rs` はルートとみなされ、その子を `tests/common/` ではなく
     `tests/` から探す。cargo はこの `common.rs` 自体も別のテストクレートとしてビルドするので、実際には `tests/common/mod.rs` の形が使われる
   - `lib.rs` や `main.rs` という名前の、ルートではないモジュール
   - `#[path]` で読み込まれたファイル。ルートとして扱われる。子モジュールの探し方は rustc と同じになるが、モジュール名は失われる。
     モジュール名は prelude の判定にしか使わない
3. **子モジュールのファイルが見つからないときは報告しない方を採った。** 判定できない状態を違反にしないためである。
   別案は「モジュールのファイルが見つからない」違反を新しく足すことだが、旧 lint には無い規則なので入れていない
4. **`#[cfg_attr(..., path = "...")]` を `#[path]` とみなす方を採った。** 旧 lint は、条件が成り立つビルドでだけ `#[path]` として扱った。
   条件を評価できないので、`#[path]` の禁止を cfg_attr ですり抜けられない方を選んだ
