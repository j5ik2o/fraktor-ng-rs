# rustdoc（旧 rustdoc-lint、`rustdoc_lint`）

## 旧 lint から写したもの

- **テキスト走査のまま写した。** 行頭（先頭の空白を除いた位置）が `///` か `//!` の行を doc コメントの行と見なし、
  同じマーカーが続く行を 1 ブロックにする。空行、通常の `//` コメント、別のマーカー、属性の行でブロックは切れる
  （rustdoc は属性をはさんだ doc を 1 つに連結するが、旧 lint は別ブロックとして扱った）
- マーカーのあとの空白 1 文字までを取り除いた残りを本文とする（旧 `content_column`）
- フェンスの判定は、本文の先頭の空白を除いて ```` ``` ```` で始まる行。開閉は交互に切り替わり、状態はブロックごとに初期化される。
  `~~~` と 4 つ以上のバッククォートは特別扱いしない（```` ````ignore ```` は情報文字列が `` `ignore `` になり `ignore` に一致しない）
- `ignore` の判定は、開きのフェンスの情報文字列を `,` と空白で分けた語のどれかが、大文字小文字を無視して `ignore` に一致すること。
  閉じのフェンスは見ない。`ignored`、`ignore-test` は一致しない
- 日本語の判定は旧 `is_japanese_char` の範囲そのまま（U+3000–303F、3040–309F、30A0–30FF、31F0–31FF、3400–4DBF、
  4E00–9FFF、F900–FAFF、FF66–FF9F、FFE0–FFEE）。全角英数（U+FF01–FF5E）は含まれない。範囲の端は合成テストで確かめた
- 日本語の報告は、フェンスの外の本文で、1 ブロックにつき最初の 1 文字の位置に 1 件だけ。`ignore` の報告は、開きのフェンスごとに 1 件
- 報告位置は、`ignore` は本文の先頭、日本語は見つけた文字。行は旧 `.stderr` の最初の `-->` と一致する。
  桁は rustc と同じく文字数で数える（バイトではない）
- 旧 lint はアイテム（`check_item`、`check_trait_item`、`check_impl_item`、`check_foreign_item`）を訪れたときに
  そのファイルを 1 度だけ解析した。アイテムが 1 つも無いファイルは解析されない。同じ条件を、
  トップレベルにアイテムがあることとして写した。`macro_rules!` の定義は HIR に残らないので数えない

## テキスト走査を選んだ理由

syn で doc 属性を辿り直す案は取らなかった。次の点で旧 lint と結果が変わるからである。

- 旧 lint は文字列リテラルやブロックコメントの中の行頭 `///` も、`////` で始まる通常のコメントも doc と数えた。
  syn では doc 属性にならない
- 旧 lint は属性をはさんだ doc を別ブロックと数える。syn の doc 属性は連結される
- 旧 lint は `/** */` と `#[doc = "..."]` を見なかった。syn では doc 属性として現れ、区別に元のテキストが要る

この違いは偽陽性・偽陰性の両方向にあるが、旧 lint を忠実に写す方針に従い、結果が同じになるテキスト走査を選んだ。
該当する形は `tests/ui/synthetic/rustdoc/text_scan.rs` と `block_grouping.rs` に残した。

## 写せなかったもの、変えたもの

- 旧 lint の対象は、コンパイルに含まれるファイルだけだった。新チェッカーは検査対象のパスの下の `.rs` をすべて見る
- cfg で除かれたアイテムも、アイテムの有無の判定では数える（cfg は評価しない）
- マクロが生むアイテムは見えない。ファイルにマクロ呼び出しのアイテムしか無い場合は、アイテムがあるものとして解析する
- 旧 lint が出していた `help` と AI 向けの `note` は、1 件のメッセージに畳んだ。UI テストの照合は行だけで行う

## 例外規定と抑制

- 旧 lint の `#[allow(rustdoc_lint)]` は、ファイルの最初のアイテムか crate に付けたときだけ効いた。診断が
  「最初に訪れたアイテム」のレベルで出ていたからである。コメント指定は、書いた直後の要素の範囲全体にかかる
  （`// syn-check: allow(rustdoc) -- <理由>`）。doc が付いた要素の直前に書けば、その doc と本体の中の doc に効く。
  ファイル先頭の `//!` はどの要素にも属さないので、`allow` は書いた次の 1 行にしか効かない。`//!` には `allow-file` を使う

## 配置ごとの違い

- なし。旧 lint はパスを見ないので、`Layout::Ng` と `Layout::Legacy` で同じ結果になる（合成テストで両方を確かめた）

## 既知の限界

- 上記のとおり、テキスト走査なので、文字列リテラルやブロックコメントの中の `///` を拾う（旧 lint と同じ）

## 要判断

- テキスト走査の癖（文字列リテラルとブロックコメントの中の行頭 `///` を拾う、`/** */` と `#[doc]` を見ない）を
  このまま残すか、syn の doc 属性ベースに直すか。直すと旧 lint と結果が変わる。暫定では旧 lint どおり
